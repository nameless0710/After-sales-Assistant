# 商品售后查询台

双击项目目录中的 **启动商品售后查询台.cmd**。输入商品编码并按回车，日期默认为上海时间三个月前一号至今天，发货仓默认为所有仓库。点击发货仓按钮打开窗口，输入部分仓名可实时筛选。可逐项勾选，或批量勾选、取消勾选筛选结果，再点击「确定」。清除搜索后会显示完整列表并保留勾选状态。仓库窗口显示已有报表中出现过的仓库，也可以点击「从 ERP 更新」。首次在工具打开的 Chrome 或 Edge 窗口登录。若 ERP 停留在首页，可从「报表」进入「销售主题分析」，然后保持窗口打开。

## 查询与复核

单击「匹配商品」打开勾选窗口。默认全选，可输入部分商品编码实时筛选，再批量勾选或取消勾选当前筛选结果。清除搜索可重新查看完整清单，已修改的勾选会保留。至少保留一项后点击「确定」，再点击「查询」。更改主窗口的商品编码会恢复默认全选。手动只选部分商品时，补发备注按所选完整编码匹配。单击「实发」「退货」「补发」或「售后率」查看订单，也可导出所见明细。订单报表可能省略逐行 SKU，所选范围可在匹配商品窗口查看。「数据 → 查看案例一」可打开本机已发布的完整查询，点击「补发 9 单」可复核订单号。在没有完整查询的电脑上，此菜单会用项目目录中的两份抓包和补发工作簿做离线核对。

实发和退货按件计。工具按内部订单号分别累加实发和退货，累计大于零的订单各计一单。补发按内部订单号去重。售后率为（退货单数＋补发单数）÷ 实发单数，分母为零时显示「—」。

补发筛选包括编码含“补发专用”的全部启用商品。卖家备注先匹配所选完整编码，再匹配管理员确认的简称。简称在 `remark-aliases.json` 按查询编码维护。案例一的简称只对整组 `龙竹-50-60cm` 生效。单独查询某个规格不会继承整组简称。

## 数据与刷新

今天已成功采集过的相同查询可以直接读缓存。「重新采集」会重新生成报表。每次发布前检查日期、仓库、全表行数、实发合计和退货合计。查询失败时界面标明旧结果的商品、日期、报表更新时间和采集时间。登录超时或程序中断后，打开「数据 → 恢复未完成的查询」重跑。

数据默认保存在当前 Windows 用户的 `%LOCALAPPDATA%\AfterSalesDesk\data`。如需共享，在采集机和各客服电脑将环境变量 `AFTERSALES_STORE` 指向同一个部门共享目录。共享盘须支持文件锁和同目录原子替换。网页登录状态仅保存在各自电脑的专用浏览器目录。建议由一台采集机运行每日任务。

在「数据 → 每日自动刷新」查看 Windows 计划任务的状态、运行时间和是否补跑。可开启或重设为每天 08:30，也可关闭后续触发。新版设置错过当天时间后不补跑。已存在的旧计划会沿用现有设置，直到关闭或重设。计划使用当前已登录的 Windows 用户和专用浏览器。点击「每日关注」可订阅或取消当前商品和仓库。

```powershell
& '.\report-desk\启用每日刷新.ps1' -Mode Status
& '.\report-desk\启用每日刷新.ps1' -Mode Enable -Time '08:30'
& '.\report-desk\启用每日刷新.ps1' -Mode Disable
```

当日任务按发货日期刷新整个查询期，涵盖历史发货单新增退货。集中采集默认从月份开始，单次超过 40,000 行或下载不完整时缩短日期区间。当天重跑会复用已校验的分段。下次刷新沿用上次成功的分段边界。所有分段校验成功才发布本批结果。可双击 `daily.cmd` 立即刷新。日志位于 `%LOCALAPPDATA%\AfterSalesDesk\daily.log`。在 Windows 任务计划程序中可停用 `AfterSalesDesk-Daily`。

## 验证全商品采集

初始采用按商品查询。要切换为本地全商品筛选，先选取两个完整 SKU，在相同数据更新时间、发货日期和仓库条件下，正式导出四份完整 Excel。第一份为「明细（订单商品）」，包含 A、B；其余三份为「明细（订单）」，分别仅选择 A、仅选择 B、同时选择 A 和 B。样本至少包含一笔同时发出 A、B 且只退一种商品的订单。

也可以运行 `验证商品归属.ps1 -Day 2026-11-01` 由浏览器生成单日订单商品明细，从中选择符合条件的一笔混合订单，再按 A、B 和 A+B 三组生成正式报表并对账。验证失败时继续使用按商品采集。

从 `report-desk` 目录运行以下命令，把示例文件名和 SKU 替换成实际值。

```powershell
..\runtime\bin\java.exe '-Dfile.encoding=UTF-8' -cp 'report-desk-desktop.jar;../lib/*' Desk --verify-grain A B '订单商品.xlsx' 'A订单.xlsx' 'B订单.xlsx' 'AB订单.xlsx'
```

工具对四份报表逐单核对实发、退货。验证通过后，每日任务分段下载全商品订单商品明细和补发订单，整批发布为 `bulk.zip`。同一数据更新日，某个商品组首次查询时，会与网页按该组商品筛选的完整订单报表核对内部订单号、发货日、仓库、实发、退货及补发归属。全部一致时可以查看集中数据中的商品行。如果两种报表对个别退货订单的归属不同，该商品组采用网页订单结果，界面会注明来源。

校验结果保存在 `verified-groups`。同事查询同一组商品、相同或更短的日期范围，或在已验证的全仓结果中选一个仓库，都可以本地计算。关注的商品由每日任务预先复核。全商品批次包含匹配未来商品所需的补发卖家备注，共享目录权限应限于业务人员。按商品发布的明细仅保留命中词。

实际核验中发现，个别订单在「订单商品明细」中有实发为零、退货为一的商品行，而按该商品筛选的「订单明细」没有这笔订单。因此，新商品组会先核对网页结果。工具保留两种来源，按核验结果显示相应数据，并在界面说明采用的来源。

## 页面适配

浏览器从 ERP 主界面进入报表，在可见的 iframe 中定位筛选条件，独立在活动订单框架中读取汇总并点击导出。`browser-settings.json` 中的 `controls` 支持为变动的页面控件配置 CSS 选择器，例如 `picker`、`skuInput`、`shippedSum` 或 `returnedSum`。总计控件须指向相应的合计数字单元格。定位失败会在界面给出控件名并保留已发布结果。

整套部署需要本目录、上一级的 `runtime`、`lib` 以及启动脚本。本机须安装 Chrome 或 Edge。Windows 上无需另装 Java 和 Node。采集、统计和导出在本机运行。

首次使用时，把「更新工具.cmd」和 `update.ps1` 放在同一个可写目录，双击更新工具从 Gitee 安装。需要共用数据的电脑按前述方式配置同一个共享目录。在多个电脑部署时，只在负责采集的电脑上启用每日任务。

## 更新工具

双击「启动商品售后查询台.cmd」会先检查 Gitee 上的运行文件，校验并替换变化的文件后打开查询台。Gitee 暂时无法连接时，启动器会尝试打开已安装版本。也可关闭查询台并等待采集结束，再双击「更新工具.cmd」单独同步。网络需要代理时，可配置 `AFTERSALES_UPDATE_PROXY`，或将维护者提供且支持 Gitee 的可信 HTTPS 转发前缀写入安装目录的 `update-source.txt`。如自行修改过 `browser-settings.json` 或 `remark-aliases.json`，请先备份。
